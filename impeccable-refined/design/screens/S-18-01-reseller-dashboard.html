Layout

  • 375 mirrors the Flutter screen: blurred header (profile avatar + Lighthouse logo) over one column: 2 metric cards side by side, "Orders Awaiting Response" with "View All", the caption, and one bordered container of up to 5 order rows divided by hairlines; space below for the floating reseller bar.
  • 768: the same order beside the reseller rail. The header shows the page name and a Refresh button; each order row puts Reject and Submit Quote on its right.
  • 1440: a content column (max 960) beside the reseller sidebar: metric cards in one row, then the list. Reject, Submit Quote and order details open the F-19 screens (S-19-06, S-19-04, S-19-03).
  • Order row: 72 thumbnail, order number and status text, product title (2 lines), brand chip and price (or "On Request"), "SKU: {sku}" and "Quantity: {NN}". Requested orders show Reject + Submit Quote and are not tappable; Won and Rejected (delivery rejected) rows open the order details and have no buttons.
  • States: default, loading (values "-", no trend, caption "Loading requests...", 4 skeleton rows), empty, error (API message in the empty layout; cards stay "-").

Components used

  • Top header · Avatar · IconButton glass (Refresh, from 768)
  • Metric card (label, value, trend with direction icon) · Section header + Button text (View All)
  • Tag (brand chip) · Button stroke S (Reject) · Button filled S (Submit Quote)
  • Skeleton · Empty state (icon + message) · Reseller nav bar / sidebar (F-04)

Motion

  • Blocks rise in: --stagger-*; skeleton to content: --shimmer-*, --skel-*, --reveal-*
  • Press on rows and buttons: --press-*; View All, order details, Reject and Submit Quote: --page-slide-*

Accessibility

  • Landmarks: banner, main, reseller navigation. The page has no visible title on mobile in Flutter (logo only), so a hidden h1 "Dashboard" names it; from 768 the title is visible.
  • Avatar link is labelled "Open profile". Metric cards are a description list read as label, value, trend; the trend states "Up" or "Down" in text, not only by colour or icon.
  • Tappable rows are single links named with order number, status and product; other rows expose only their two buttons, labelled with the order number.
  • The caption is a polite live region, so "{shown}/{total} active requests" is announced after a refresh; the error message is an alert.

Decisions to confirm

  • Error: no retry button, as in Flutter (pull to refresh only); from 768 the header Refresh button is the retry. A stats failure is silent: the cards stay at "-".
  • "Dashboard" title from 768 is a web addition taken from the proposed nav label (Q-48).
  • Zero change is drawn as positive (up icon, success colour), as in Flutter ("No change this week").
  • Trend glyphs: Flutter uses Material trending icons (Q-34); TradeUp / TradeDown are used. Empty icon: LicenseDraft is not in ICONS.md; File02 is used. Thumbnail placeholder Image01 → Image02.
  • Trend colours: --success-strong / --danger-strong, and the lighter --success-soft / --danger-soft in dark theme.
  • Status is plain text ("New", "Quoted", "Won", "Delivered", "Rejected", "Completed", "Cancelled") as in Flutter, not a status pill.
  • The caption in the empty and error states follows the "{shown}/{total} active requests" pattern with zeros.
