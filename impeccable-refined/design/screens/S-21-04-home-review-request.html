Layout

  • 375: as the app. Back, centred title and subtitle. Intro line, "WHAT YOU ARE SHARING" with the summary card, "WHO RECEIVES IT" with the count under it, recipient cards 8 apart, ADD MORE, the notice, SAVE AS PRIVATE DRAFT as a centred text button. SEND REQUEST is pinned with its helper when disabled. No bottom tab bar.
  • 768: the same single column, centred at 640.
  • 1024 and up: a split. The summary on the left, recipients, notice and ADD MORE on the right in a sticky column. SAVE AS PRIVATE DRAFT moves into the bottom bar as the secondary button beside SEND REQUEST.
  • States: default build request, two recipients ticked · repair repair rows, "ADD MORE CONTRACTORS", the longer notice · professional find-professionals rows, three recipients · lighthouse Get started: the Lighthouse card, no count, no ADD MORE, always enabled · empty nobody ticked: "0 professionals", disabled button with the helper · loading while send or save runs: every control disabled, no spinner as in the app.
  • There is no error state: writes are local in the app.
  • In the mockup the recipient cards toggle, the count line follows, and the footer swaps between enabled and disabled.

Components used

  • Navigation shell · Top header (glass) with Back · Section header (shared, f-20.css)
  • New: labelled summary row card (.nw-sum, a description list with hairlines), shared with S-21-05 · Lighthouse recipient row (.nw-lh)
  • Recipient tile: the results-screen tile (.nr-row from S-21-03) with avatar, role, rating, projects, distance and the check disc
  • Info banner (.note) · Button text, translucent, filled · Sticky footer CTA bar · Toast

Motion

  • Arrival and Back: --page-slide-*.
  • Recipient tick: --select-check-* (Flutter 150 ms fill, tick after 80 ms over 250 ms). Card and button press: --press-*.
  • Save toast: --toast-*. Nothing else moves.

Accessibility

  • h1 "Review request", the subtitle follows it. h2 for both uppercase section labels.
  • The summary is a description list: label as term, value as definition, icons hidden.
  • Recipients are a group of checkboxes "Send the requirement to name", ticked by default. The count is a polite status.
  • The notice is a note placed before the actions. The disabled SEND REQUEST is described by the helper line, which is also a polite status.
  • While busy the page sets aria-busy and a status says "Sending request". SEND REQUEST is never focused automatically.

Decisions to confirm

  • Glyph swaps (Q-162): File01 to File02 (section header), UserGroup to UserMultiple, Note01 to PencilEdit01 (Details), Image01 to Image02 (Photos), Wallet01 to Invoice01 (Budget, find professionals), Briefcase01 to Briefcase02 (Help with), LayoutGrid to FloorPlan (Spaces), Call to Call02 (Lighthouse).
  • Colour mapping (Q-161): the lavender notice gradient becomes the info banner on --accent-tonal; recipient cards use the select-card surface --element-bg-select-card-card-default; the Lighthouse card is the neutral surface with a hairline.
  • Web difference, asked for in review: recipients use the S-21-03 tile, so the avatar and text open the profile and the disc toggles the tick. In the app the whole card toggles and "View profile" is text only (Q-180).
  • The "Edit" action on "WHAT YOU ARE SHARING" is not shown: the app never enables it (Q-180).
  • The spec shows the split at desktop only; here it starts at 1024 so the two columns keep a readable width.
  • After SEND REQUEST, Back from the confirmation returns to results with the ticks still on (Q-180).
