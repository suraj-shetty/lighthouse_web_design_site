Layout

  • 375: glass bottom sheet opening at 94% height: handle, title, subtitle, search field, scrolling list, SAVE pinned at the bottom.
  • 768 / 1440: side sheet from the right, opened from the header location selector; the list scrolls inside and SAVE stays pinned. A close button is added (no drag handle).
  • List order: "Use Current Location" (when a GPS location is known) → search results while typing → Saved Addresses → Last Used Locations (max 10). Saved Addresses hide while there is search text.

Components used

  • Bottom sheet / side sheet · Search input (with clear)
  • Location row (icon, name, address) · group headings
  • Button filled L (SAVE, with loading) · IconButton (clear selection, danger)
  • Skeleton rows · Empty state · Toast (danger)

Motion

  • Open / close: --panel-*
  • Results: --skel-*, --shimmer-*, --reveal-*
  • Row and button press: --press-*; toast, --toast-*

Accessibility

  • Dialog named "Location"; focus moves to the search field and returns to the location selector; focus is trapped; Esc closes without saving.
  • Group headings are real headings; each row is one button named by its name and address; the selected current-location row exposes a pressed state.
  • The delete glyph is labelled "Clear selected location". "No results found" and "Searching" are announced politely.

Decisions to confirm

  • Tapping a Saved Address or Last Used row saves and closes in one tap; a search result or "Use Current Location" only sets the draft and needs SAVE (as the app).
  • GPS becomes the browser location prompt; the app's permission messages are reused as toasts ("Location" / "Location permission denied", etc.).
  • Leading glyphs (navigation-03 for current location, clock-01 for recent) are web choices; the app uses one pin glyph for every row.
  • Place-details failure shows the server message; "Unable to fetch place details" is sample text.
