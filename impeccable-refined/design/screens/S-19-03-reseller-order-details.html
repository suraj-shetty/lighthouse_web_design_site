Layout

  • 375: mirrors the app: full screen without the reseller tab bar. Header: title + status pill, "Order {number}" under it, close X. Cards in the app's order: product & buyer → quote details → decline / rejection details → delivery proof images → invoices → client review. Action bar pinned at the bottom (one button, or two side by side).
  • 768: same single column beside the glass menu; actions right-aligned in the sticky bar.
  • 1440: two columns: product & buyer, proof and invoices on the left; quote, decline / rejection and review on the right. On the Orders tab (S-19-01) the same sections fill the detail pane.
  • States are the seven variants plus their sub-states: "default" is Accepted (Won); then quoted, delivered (and no-proof), rejected, completed (request review → requested → submitted), cancelled, declined; plus calling, call-failed, loading and error.
  • Phone row and call button show only for Won, Delivered, Rejected, Completed and Cancelled. The buyer name is masked and the number is always hidden.
  • Answered (Q-15): an order opened without a variant whose status is not mapped (including "requested") shows this Accepted layout, as the app.

Components used

  • Top header · IconButton glass (close) · Status pill
  • Product card (list layout) · Tag · Key / value list · IconButton glass-success (call buyer, with spinner)
  • Note (decline / rejection line) · Image grid → gallery viewer (S-05-12) · Invoice row → PDF / image preview (S-05-13 / S-05-11)
  • Rating · Tag · Button filled M (Request Review, RETRY)
  • Sticky CTA bar · Button translucent L (CANCEL / CLOSE) · Button filled L (MARK AS COMPLETED / RESOLVE ISSUE)
  • Skeleton (detail) · Empty state (error) · Toast

Motion

  • Push / close: --page-slide-* under 768, --panel-* from 768
  • Skeleton to content: --skel-*, --shimmer-*, --reveal-*
  • Proof image / invoice open: --mediaview-open-dur
  • Press: --press-*; toasts, --toast-*; review card change, --text-swap-*

Accessibility

  • Title is the h1; section labels (QUOTE DETAILS, DELIVERY PROOF IMAGES, …) are h2.
  • Label / value pairs are a description list.
  • The masked phone is announced as "Hidden"; the call button is labelled "Call buyer (masked number)" and announces "Calling buyer" while busy.
  • Proof images have alt text "Delivery proof image n of N"; invoice rows are named with the file name and type.
  • Status is pill text; toasts are polite live regions; "Request Review" announces its busy state.

Decisions to confirm

  • Open (Q-131): "CANCEL" on Won / Rejected only closes the screen; it does not cancel the order. Keep the wording?
  • Open (Q-28): the call button opens the device dialer with a masked number that is never shown. What should a desktop browser without a dialer do?
  • The error icon uses InformationCircle; the app uses Alert02, which is not in ICONS.md. The call glyph is Call02 (app: Call); the review badge is CheckmarkCircle01 (app: CheckmarkCircle02).
  • "Additional Charges" prints the amount without a currency symbol, as the app ("Transport 1200, Handling").
  • From 768 the spec suggests a side sheet over the list; here the details are a page, and the Orders tab shows them in its pane from 1200.
