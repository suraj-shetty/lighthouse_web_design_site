Layout

  • 375: glass bottom sheet: handle, centred title and subtitle, a 48 high pill that is either the Profile / Cover toggle or a static label, two equal tiles (Camera, Gallery) with icon over label, full-width REMOVE PICTURE.
  • 768 / 1440: the same content as a 360 wide popover anchored to the control that opened it (pencil, cover or avatar on Manage Account).
  • States: toggle (opened from the pencil: Profile / Cover segments, Profile preselected) · profile (opened from the avatar: static "Profile") · cover (opened from the cover: static "Cover").

Components used

  • Bottom sheet / popover
  • Segmented toggle (.seg) · static label pill
  • Select-card style tiles (Camera, Gallery)
  • Button glass L (REMOVE PICTURE)

Motion

  • Open / close: --panel-*
  • Segment change: --tabs-*
  • Tile and button press: --press-*
  • Camera / Gallery close the sheet and continue to the cropper S-13-07, preview S-13-08, loader S-13-09; REMOVE PICTURE closes the sheet and shows the loader

Accessibility

  • Dialog named "Update Photo"; focus trapped and returned to the trigger.
  • The toggle is a labelled group of two pressed-state buttons ("Photo to update"); in build it should behave as a radio group with arrow keys.
  • Tiles are buttons with visible text; Gallery is a native file input in build so it is reachable by keyboard.

Decisions to confirm

  • Gallery opens the browser's file chooser (JPEG / PNG); Camera is shown only where a capture device is available: otherwise Gallery takes the full width (web adaptation of image_picker).
  • Camera03 is not in ICONS.md; Camera01 is used. Gallery keeps the app's File02 glyph.
  • In the mockup both tiles of the toggle state continue to the profile cropper regardless of the selected segment.
  • Browser camera permission prompts are not designed (F-13-Q12).
