Layout

  • 375: glass bottom sheet over the scrim: drag handle, title, subtitle, one pill row with the fixed label on the left and the value on the right, "UPDATE".
  • 768 / 1440: side sheet from the right over Manage Account (440 wide, no drag handle); same order, actions pinned to the bottom.
  • One reusable sheet, five configurations: one state each: default Brand/Company Name (Brand), company-name, reseller-handle, legal-business-name (Reseller), key-contact-person (both). Manage Account opens the right one with data-open-state.
  • unset, editing, error, saving, server-error are drawn on the Brand/Company Name configuration; they are identical for the other four apart from the label, hint and message.

Components used

  • Bottom sheet / side sheet
  • IconButton glass (close)
  • Text field (pill, inline label): default, focus, error, disabled
  • Button filled L (UPDATE, with loading)
  • Toast danger

Motion

  • Open / close: --panel-*
  • Button press: --press-*
  • Error toast: --toast-*
  • Field focus / value swap: --text-swap-*

Accessibility

  • Dialog named by its title; focus moves into the sheet, is trapped, and returns to the Manage Account row that opened it; Esc or the scrim closes without saving.
  • While saving the primary button is disabled and announces its busy label; toasts are announced through a polite live region.
  • The visible label ("Name" / "Reseller Handle") is the input's programmatic label; the error text is tied to it with aria-describedby and announced.

Decisions to confirm

  • The app's tap-to-edit row is an ordinary always-editable input on web (feature web disposition).
  • error shows the "cannot be empty" message inline. The app computes it but never displays it (the tap is silently ignored): confirm web should show it. Messages: "Brand/Company name cannot be empty" (also Company Name), "Reseller handle cannot be empty", "Legal business name cannot be empty", "Contact person name cannot be empty".
  • Reseller Handle: the leading @ is stripped on save; no format or uniqueness check here (Q-117).
  • State server-error shows the sheet as it stays after a failed request, with the "Error" toast (server message, else "Network error occurred" / "Something went wrong. Please try again later."). No retry control, as the app.
