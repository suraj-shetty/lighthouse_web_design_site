Layout

  • 375: mirrors the app: full screen. Header "Accepted Order" + "Won" pill, "Order {number}", close X. Column: product card (image, title, tag, "Required Quantity") → "DELIVERY PROOF IMAGES" dashed box with "Browse" → "{n} Images Uploaded" + image file rows → "FINAL INVOICE & WARRANTY CARD" dashed box with "Browse" → invoice file rows. Bottom bar: "GO BACK" and "SAVE".
  • 768: same column beside the glass menu; buttons right-aligned in the sticky bar.
  • 1440: the two upload sections sit side by side; the dashed boxes also accept drag-and-drop ("dragging" state).
  • "Browse" is a real file input (multi-select; png / jpeg for images, pdf / png / jpeg for invoices). "SAVE" is disabled until there is at least one image and one invoice file.
  • Image rows show the file name only (no thumbnail), as the app; invoice rows show type badge, name, size and "Completed".
  • On success the toast shows and both this screen and Order details close. There is no fetch on open, so no loading skeleton; "saving" is the busy state.

Components used

  • Top header · IconButton glass (close) · Status pill · Product card (list layout) · Tag
  • File drop zone · Uploaded-file row · Button filled S (Browse) · IconButton plain (remove)
  • Sticky CTA bar · Button translucent L (GO BACK) · Button filled L with loading (SAVE) · Toast success / danger

Motion

  • File rows appearing: --stagger-*; drop-zone highlight, --duration-fast
  • Press: --press-*; toasts, --toast-*; close, --page-slide-* / --panel-*

Accessibility

  • Each box is a labelled file input; the format / size / count line is its description; "Browse" is keyboard operable.
  • File lists are lists; each remove button is named "Remove {file name}"; the count line is a status region.
  • Disabled "SAVE" explains what is missing; while uploading it announces "Uploading delivery proof". Section labels are h2.
