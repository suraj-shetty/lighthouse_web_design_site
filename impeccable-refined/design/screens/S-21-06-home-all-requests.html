Layout

  • 375: as the app. Back and a left-aligned title, a scrolling row of six status chips with counts, then rows: 90 by 76 thumbnail, title over two lines with the status text at its right, one line under it. No hairlines, no footer, no bottom tab bar.
  • 768: a list with hairlines between rows. Each row is one line: thumbnail, title, the "Sent to" or location line, status at the right end.
  • 1440: the same list capped at 960 so the columns stay close enough to scan. Rows are not turned into cards.
  • States: default six requests, "All" selected. The chips work: Responses and Confirmed are empty and show the empty text. empty no requests at all: every chip reads 0 and shows the same text.
  • Loading and error do not apply: the app reads the list from memory and has neither.

Components used

  • Navigation shell · Top header (glass) with Back · Chip as tabs with counts
  • New: request list row (.na-row: thumbnail, title, status text, one line), text-only empty lines (.na-none)

Motion

  • Arrival and Back: --page-slide-*. Chip change: --tabs-*. Row press: --press-*.

Accessibility

  • h1 "All requests". Chips are a tablist "Request status" with the count in the name ("Drafts, 2"). Counts use tabular figures.
  • Each row is one link named "title, status, second line"; the thumbnail is decorative. Rows are at least 44 high.
  • The empty text is a polite status, so a chip change announces it. Status is text, not colour.

Decisions to confirm

  • Responses and Confirmed always read 0: the app never produces those statuses (Q-178). Keep the chips on web?
  • There is no delete, dismiss or edit here, as in the app. A row opens results, review, the explore list or the read-only view depending on its journey and status.
  • An explore request has no location, so its second line is blank, as the app shows it.
  • Thumbnails follow need_request_text.dart (type, trade or who image). The Home card for the kitchen renovation uses the renovation intent photo instead.
  • From 768 the rows gain hairlines; under 768 they are 16 apart with none, as in the app.
