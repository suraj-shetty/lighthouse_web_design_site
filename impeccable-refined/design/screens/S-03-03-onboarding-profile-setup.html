Layout

  • 375: as the app: back + progress (last segment current); title, subtitle; centred circular photo with a "+" badge; labelled fields Name *, Username *, Current Location *, Email; Submit stays pinned under the scrolling form.
  • 768: centred card with the same single column.
  • 1440: wider card: photo in a side panel on the left, fields in two columns on the right, Submit right-aligned.
  • States: default (empty, placeholder photo, Submit enabled: validation runs on tap), filled (photo chosen, username available), invalid (per-field errors after Submit), taken (username already taken), loading (skeleton replaces the form during upload / save), error (toast; the form returns with the entered values). No empty state.

Components used

  • IconButton solid (back)
  • Progress (segmented bar)
  • Avatar with add badge (opens S-03-05)
  • Text field: leading icon, trailing status icon, error text
  • Select (read-only location field, opens S-03-04)
  • Button filled L · Skeleton · Toast danger

Motion

  • Username status icon: --icon-swap-*; pickers, --panel-*; Submit, --press-*.
  • Loading: --skel-*, --shimmer-*; to the home shell, --page-slide-* under 768, --panel-* from 768; back to step 1, --tab-panel-*.

Accessibility

  • h1 = title. Every field has a visible, programmatic label; required fields carry aria-required and a visible asterisk.
  • Errors are tied to their field and announced; username availability is announced politely ("Username available") and shown with an icon, not colour alone.
  • The photo control is a button "Add profile photo"; the location field is a button that opens a dialog. Focus order follows the visual order, Submit last.

Decisions to confirm

  • Q-04 applied: a taken username blocks Submit; minimum username length is 3 (2–15 characters of a–z, 0–9, ". _ -", forced lowercase, no spaces).
  • Glyph: the app uses User03 for Name and Username (not in the icon font); User is used.
  • The app shows a bundled default-profile image; the mockup shows a neutral avatar placeholder.
  • Progress is drawn with 3 segments (Professional path); other roles have 2.
