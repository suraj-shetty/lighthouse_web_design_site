Layout

  • 375: as the app: location selector and filter on row 1, search on row 2, scrolling role tabs on row 3, one column of cards, glass tab bar.
  • 768: floating glass bar: location, search and filter in one row, tabs beneath; cards in 2 columns; collapsed menu.
  • 1440: same bar; cards in 3 columns (2 or 4 as the menu collapses or the window grows), content capped at 1120.
  • Each role tab is its own state with its own results; tapping a tab reloads the list, and a card opens that category's profile (S-07-01).
  • Business tabs (names containing brand, reseller, retailer, distributor) use the landscape 3:2 image and drop chips and stats.

Components used

  • Navigation shell (shared) · Top header (glass)
  • Search input · IconButton glass with dot badge · Location selector
  • Chip as role tabs (scrolling tablist)
  • Result card (Shop card, list layout) · Avatar image · Verified badge · Tag (New = dark, role = neutral) · Metric cells
  • Skeleton (pills + cards) · Empty line · Toast (danger)

Motion

  • Menu tap (Home ⇄ Discover): pill stretch + content blur out, then pill settle + staggered rise: see S-05-01 notes.
  • Results entrance and next page: --stagger-*; skeleton, --shimmer-*, --skel-*, --reveal-*
  • Tab select: --tabs-*; card and button press, --press-*; filter dot, --badge-pop-*; toast, --toast-*
  • Location and filter sheets (S-08-02, S-08-03): --panel-*

Accessibility

  • Visually hidden h1 "Discover"; search landmark with a labelled input; tabs are a tablist.
  • Filter button says "Filters, 2 applied" when the dot shows. Each card is one link; verified is announced in text.
  • Empty line is a polite status; toast is a polite live region. Targets are 44 or larger.

Decisions to confirm

  • Tab names, people and brands are sample data; the real tabs come from the backend.
  • Error = toast then the empty line (Q-06); no retry control exists in the app for this screen.
  • Card images have empty alt text because the card link is named by the heading (Q-36).
