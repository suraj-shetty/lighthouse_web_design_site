Layout

  • 375: as the app: back arrow + title, scrolling multi-select list of glass pill rows (label left, checkbox right), "Save" above "Cancel" pinned at the bottom, floating over the tab bar.
  • 768: options in two columns inside a 720 column beside the rail; "Cancel" and "Save" sit side by side, right-aligned, in the sticky footer.
  • 1440: same 720 column beside the sidebar; reached from Manage Account and returns to it. The list is short text, so it is not stretched wider.
  • Options are sample data: the real names come from GET /v1/category?tags=marketplace. Only the entities of the saved parent categories are listed, flat, as the app.

Components used

  • Top header (back + title)
  • IconButton plain (Back)
  • Checkbox option rows
  • Footer / sticky CTA bar
  • Button filled L (Save, with loading) · Button translucent L (Cancel)
  • Skeleton rows · Toast danger

Motion

  • Route push / pop: --page-slide-* (desktop: --panel-* crossfade)
  • Option toggle: --select-check-*
  • List entrance: --stagger-*; skeleton to content, --skel-*, --shimmer-*, --reveal-*
  • Button press: --press-*; error toast, --toast-*

Accessibility

  • Main landmark; the title is the page h1; Back is labelled.
  • Options are a checkbox group labelled "Product Sub Categories"; each row is one 56px target with a visible label.
  • While saving, the list and Cancel are disabled and Save announces "Saving".
  • Empty text and toasts are announced politely; the tick is paired with the row border so colour is not the only signal.

Decisions to confirm

  • error = options request failed: toast "Error" + message, then the empty text (no retry control, as the app). save-error = PATCH failed: toast, stays on screen with the draft kept.
  • The spec asks for a "detail pane" on desktop; shown here as a pushed page inside the shell because Manage Account (S-13-05) owns that layout: confirm.
  • Save with no change goes back without a request; no success toast in the app, so none here.
  • Two empty states: empty (no parent category saved) and no-sub-categories (parents have no entities). Neither has a CTA in the app; a link to Product Categories would be an addition.
