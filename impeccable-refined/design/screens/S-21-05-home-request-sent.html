Layout

  • sent (confirmation), 375: no header and no Back, as the app. 52 success disc, title, body, the short summary card, BACK TO HOME pinned. No bottom tab bar.
  • viewing (read-only), 375: Back and the request title in the header; the status line as the heading, the same body paragraph, every answer in the summary card plus "Sent to"; BACK TO HOME pinned.
  • 768 and 1440: a centred column (560 for the confirmation, 640 for the view). BACK TO HOME becomes a regular button under the card, not a pinned bar. The menu is at the side, so the confirmation needs no header.
  • Other states: sent-repair the repair wording and rows · sent-lighthouse "A Lighthouse manager will call you", the "While you wait" card with SEE PROFESSIONALS as the filled action, BACK TO HOME outlined.
  • Loading, empty and error do not apply: the screen reads the stored request only.

Components used

  • Navigation shell · Top header (glass) with Back, viewing only
  • Success mark with title and body (the empty-state layout used for success) · Labelled summary row card (.nw-sum, shared with S-21-04)
  • "While you wait" block on the weak surface · Button filled, Button translucent · Sticky footer CTA bar under 768

Motion

  • Arrival: --page-slide-*. The success mark is static, as in Flutter.
  • Button press: --press-*.

Accessibility

  • Confirmation: the title is the h1, a status announced on arrival, and takes focus first; the mark is decorative.
  • Viewing: h1 is the request title, the status line is an h2.
  • The summary is a description list. "While you wait" is a labelled region with its own heading.
