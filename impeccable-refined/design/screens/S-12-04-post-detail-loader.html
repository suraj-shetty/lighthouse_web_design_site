Layout

  • Transitional: fetches the post by id, then is replaced by the post screen. On the web it is the loading and error state of the post page, not a page of its own.
  • 375: full-screen detail skeleton while loading. On failure, the message centred with a text button under it. No header or back button.
  • 768 / 1440: the same, centred at feed width beside the navigation.
  • States: loading, error (server or repo message, for example "Network error occurred", "Something went wrong. Please try again later."), missing-id ("Post id missing").

Components used

  • Skeleton (detail)
  • Empty state, error variant (message only) · Button text (Close)

Motion

  • Skeleton: --shimmer-*, --skel-*; content swap on success: --reveal-*; Close: --page-slide-*

Accessibility

  • Loading is announced as busy with a hidden page heading; the error text is an alert; Close receives focus on error.

Decisions to confirm

  • Loading and error states are kept on web exactly as the app's loader has them (Q-07): message + "Close", no retry.
  • The navigation shell stays visible on web (every signed-in screen has it); the Flutter loader is a bare full screen.
  • "Close" goes back to where the notification or link was opened; on a cold deep link there is no history, so the build needs a fallback destination (not defined in Flutter).
  • On success this is replaced by S-12-03 Post, so Back from the post never returns here. Another message the repo can return: "Data is null".
