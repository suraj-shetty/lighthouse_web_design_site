Layout

  • 375: glass bottom sheet with drag handle, title, body and two equal buttons (Cancel left, Block right).
  • 768 / 1440: centred destructive confirm dialog with the same content.
  • Title reads "Block {name}?" with the full name, else the username; with neither, "Block this user?".
  • States: default, loading (Block shows a spinner, both buttons disabled), error (sheet stays open, error toast).

Components used

  • Bottom sheet (mobile) / Modal dialog (from 768)
  • Button stroke M (Cancel) · Button destructive M (Block, with loading)
  • Toast (danger on failure; success after blocking)

Motion

  • Sheet: --panel-*; dialog: --modal-*; button press: --press-*
  • On success the sheet closes, the profile pops back to its caller (--page-slide-*) and the toast "Blocked / You will no longer see their content." shows (--toast-*). If the server answers unblocked: "Unblocked / You can see their content again.".

Accessibility

  • alertdialog labelled by its title and described by its body; initial focus on Cancel; focus is trapped and restored to the More button.
  • While submitting, both buttons are disabled and Block announces "Blocking".
  • The destructive action is told apart by its label as well as colour; toasts are polite live regions.

Decisions to confirm

  • Cancel uses the stroke button (spec: translucent with a --stroke-soft outline); Block uses --danger-default.
  • The mockup cannot finish the request: the loading state stands in for the submit, and the success toast copy is listed under Motion.
  • Failure toast message is the server message; the sample uses "Something went wrong. Please try again later.".
