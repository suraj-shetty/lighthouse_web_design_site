Layout

  • 375: as the app: back button and segmented progress in one row; title and subtitle; 2×2 grid of equal-height tiles (icon, title, description); CONTINUE at the bottom.
  • 768: centred card, tiles stay 2×2, CONTINUE under the grid.
  • 1440: wider card with the four tiles in one row; CONTINUE right-aligned under them.
  • Progress has 2 segments, and 3 once Professional is selected (try it: the bar and the CONTINUE target follow the selection).
  • States: default (nothing selected, CONTINUE disabled), selected (Homeowner), professional (3 segments), loading (skeleton replaces title, tiles and button), empty (root category failed: only back + progress), error (toast; user stays here with Professional selected).

Components used

  • IconButton solid (back → S-04-05)
  • Progress (segmented bar)
  • Select card (default / selected, with icon and tick)
  • Button filled L (disabled / active)
  • Skeleton · Toast danger

Motion

  • Tile selection: --select-check-*; progress segment, --tabs-*.
  • Step change: --tab-panel-*; loading, --skel-*, --shimmer-*, --reveal-*.
  • Exit dialog: --modal-*; press, --press-*.

Accessibility

  • h1 = title. Tiles are a radiogroup; each is read as "{title}. {description}" with its selected state.
  • Selection is shown by stroke weight, the inverted icon tile and a tick: not colour alone.
  • Progress has the text alternative "Step 1 of 2" / "Step 1 of 3". Disabled CONTINUE is exposed as disabled. Back is labelled "Back".

Decisions to confirm

  • Glyphs: the app uses Home03 and Briefcase01, which are not approved; Home09 and Briefcase02 are used.
  • The empty state is blank in the app (no message, no retry). Q-06 covers main screens only: should onboarding get a retry?
  • A tile whose backend entity is missing is not rendered; the grid then reflows.
  • Tile descriptions are the app fallbacks; the backend description overrides them.
