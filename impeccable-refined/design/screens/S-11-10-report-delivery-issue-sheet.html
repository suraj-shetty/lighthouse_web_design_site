Layout

  • 375: near-full-height glass sheet: handle, title, subtitle, five radio rows, "Description (Optional)" with a 4-line text area, "SUBMIT"; the body scrolls and the button stays pinned.
  • 768 / 1440: side sheet from the right, 440 wide, same stack; the footer stays pinned.
  • States: default nothing selected, SUBMIT disabled · ready reason selected, SUBMIT enabled · other-blank "Other" with no description: error border, message, SUBMIT disabled · loading · error (toast, sheet stays open).
  • The enablement rule runs live in the mockup: pick a reason, pick "Other", type a description.

Components used

  • Bottom sheet / side sheet · IconButton glass (close)
  • Radio option rows · Textarea (default, error)
  • Button filled L (disabled, loading) · Toast danger

Motion

  • Open / close: --panel-* (bottom sheet under 768, side sheet from 768)
  • Button press: --press-*; toast, --toast-*
  • Reason select: --select-check-*; on success, push Issue Reported (S-11-19), --page-slide-*

Accessibility

  • Dialog named by the title; the options are a radiogroup named "Reason".
  • The text area is labelled "Description"; it is required when "Other" is selected and the error is given in text as well as colour.
  • While SUBMIT is disabled a screen-reader hint says why.
  • Focus is trapped and returns to REJECT on close.

Decisions to confirm

  • The label stays "Description (Optional)" although the field is required for "Other" (F-11-Q5 is unanswered).
  • New copy, not in the app: the error line 'Describe the issue to report "Other".' The app shows a red border only.
  • The form resets each time the sheet opens, as the app.
