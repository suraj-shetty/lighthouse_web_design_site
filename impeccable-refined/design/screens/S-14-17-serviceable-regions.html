Layout

  • 375: glass bottom sheet over the scrim: drag handle, title, subtitle, search field, "SELECTED LOCATIONS" list with remove buttons (or the empty state); while a query is typed, "SEARCH RESULTS" appear above the selected list, "SAVE".
  • 768 / 1440: side sheet from the right over Manage Account (440 wide, no drag handle); same order, actions pinned to the bottom.
  • default saved locations (display name + rest of the address) · empty · searching skeleton cards · results · no-results · error SAVE with an empty list · saving · server-error.
  • The trash button removes its row from the draft (try it in default). Picking a result adds it unless the same display name + full address is already listed.

Components used

  • Bottom sheet / side sheet
  • IconButton glass (close)
  • Search input
  • Place tile (selected row with remove IconButton; result row)
  • Empty state
  • Skeleton
  • Button filled L (SAVE, with loading)
  • Toast danger

Motion

  • Open / close: --panel-*
  • Button press: --press-*
  • Error toast: --toast-*
  • Suggestions: --skel-* / --shimmer-*, then --reveal-*; added location, --stagger-*

Accessibility

  • Dialog named by its title; focus moves into the sheet, is trapped, and returns to the Manage Account row that opened it; Esc or the scrim closes without saving.
  • While saving the primary button is disabled and announces its busy label; toasts are announced through a polite live region.
  • Search results are a list of buttons; "Searching" and "No results found" are announced as status.
  • Each remove button names the location it removes.

Decisions to confirm

  • Brand only.
  • Empty-state copy is the professional "preferred project location" wording reused by the app (Q-118): kept verbatim, confirm.
  • At least one location is required to save; an unchanged list closes without a request. Search is debounced 300 ms.
  • Results show the suggestion description as one line (the API returns a single string). Locations are sample data.
  • State server-error shows the sheet as it stays after a failed request, with the "Error" toast (server message, else "Network error occurred" / "Something went wrong. Please try again later."). No retry control, as the app.
