The brighter side of architecture

Debug Version 1.0.0+1

Layout

  • 375 / 768 / 1440 — one centred column on the page background: logo, tagline beneath, version line at the bottom centre. No header, no navigation.
  • Logo width is 244/402 of the viewport on phones and capped at 280px from there up, so it never scales with a wide window.
  • State debug adds the "Debug" label above the version line (non-production builds only).
  • This screen is itself the loading state: no spinner, no skeleton, no empty or error state (as the app).

Components used

  • Brand logo (theme-swapped asset the app ships)
  • Text: SubLabel-S tagline, Paragraph-S version

Motion

  • Logo, then tagline, then version rise in sharp and staggered — --stagger-*. Stands in for the app's 2280 ms keyframe intro, which has no recipe.
  • Exit to the next screen — --page-slide-* under 768, --panel-* from 768.
  • Reduced motion: final frame shown at once, navigation without delay.

Accessibility

  • Single main; the logo is the h1 with the accessible name "Light House".
  • Tagline and version are real text. Nothing is focusable; taps do nothing.

Decisions to confirm

  • Q-40: show the splash on web on every load, first load only, or never?
  • Logo intro motion: staggered rise used; the frame-by-frame intro needs its own recipe if it is wanted.
  • Version text is the app's hard-coded "1.0.0+1" (Q-42).
