Layout

  • 375 — glass bottom sheet (90% height), three steps in one sheet: enter number → verify code → success. Buttons stacked at the bottom.
  • 768 / 1440 — side sheet from the right over Manage Account; primary button pinned in the footer; no drag handle.
  • Step 1 opens with the current number (last 10 digits) and India (+91). "SEND OTP" stays disabled until the number is valid and different.
  • Shown to Homeowner and Professional only. Business roles use S-14-06.

Components used

  • Bottom sheet / side sheet · IconButton glass (close)
  • Select (country code, opens S-02-02) · Text field (numeric, error) · helper text
  • One-time-code input (4 boxes: empty, focus, error) · Button filled L (disabled, loading) · Button translucent L
  • Success badge · Toast danger

Motion

  • Open / close — --panel-*; step change — --tab-panel-*
  • Success icon — --check-path-*; countdown text — --text-swap-*
  • Button press — --press-*; toast — --toast-*

Accessibility

  • Dialog named by the step title; focus trapped; returns to the "Phone Number" row; Esc and scrim close.
  • Number field: numeric keyboard, 10 characters, inline error linked with aria-describedby and announced.
  • Code boxes are one group with autocomplete="one-time-code"; each box is labelled "Digit n of 4". The countdown is not announced every second.
  • Busy buttons announce "Sending OTP" / "Verifying". Error border on a partial code is paired with the toast text.

Decisions to confirm

  • Answered (Q-19): a successful verify ends the session. The success step shows, then "CLOSE" goes to Sign in (S-02-01).
  • Toast "Error" / "Please enter a different phone number" exists in the app but cannot appear while the button is disabled for an unchanged number.
  • The verify failure message is the server message; "Invalid or expired code" is sample text.
  • Glyph: the app uses CheckmarkBadge04 (not in ICONS.md); CheckmarkCircle01 is used here.
  • The field has no visible label in the app; "New mobile number" is added for accessibility.
