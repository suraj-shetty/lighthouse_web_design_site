Layout

  • 375 — glass bottom sheet at 92% height: drag handle, title and subtitle, scrolling comment list, optional "Replying to" strip, input bar pinned to the bottom (own avatar, pill field, send icon) that rides above the keyboard.
  • 768 / 1440 — side sheet from the right beside the feed with the same header, list and pinned input.
  • Comment row: avatar (verified badge on the avatar) · name and short relative time · text · Reply and, where allowed, Delete · heart on the right. Replies sit under a "View n replies" / "Hide replies" toggle with smaller avatars.
  • Delete shows on the signed-in user's own comments and replies (and on every row when they are the post author).
  • Relative time formats: "just now", "{n}m", "{n}h", "{n}d", "{n}w".
  • Error: the toast only; a failed first load falls through to the empty copy (no retry, as the app).

Components used

  • Side sheet / Bottom sheet
  • Avatar + verified badge
  • Like button, small (optimistic)
  • Button text — Reply, Delete, View / Hide replies
  • Text field, pill, single line + IconButton (send, clear reply target)
  • Skeleton — 6 rows
  • Spinner — loading more, sending
  • Toast

Motion

  • Open / close — --panel-*
  • List entrance — --stagger-*; replies expand — --resize-dur
  • Like — --like-*; skeleton — --shimmer-*
  • Feed videos pause while the sheet is open and resume on close.

Accessibility

  • Dialog named "Comments"; the list is a list of articles, replies are nested lists.
  • The field has the label "Add a comment"; the 100-character limit is announced; Send is disabled while the trimmed text is empty or only the "@username" prefix.
  • Like buttons carry pressed state; the replies toggle exposes expanded state.
  • New comments and errors are announced in a polite live region; focus stays in the field after sending; focus is trapped and returns to the card's comment button.

Decisions to confirm

  • Subtitle is "Leave a comment about this project" on posts too (Q-51) — kept verbatim.
  • "Replying to {name}" and "Reply to {name}..." have two spaces in the app source — kept; confirm it is not a typo.
  • Send glyph: the app uses Sent02, which is not in ICONS.md; Navigation03 is used instead.
  • Delete has no confirmation in the app (Q-56) — kept: the row is removed at once and restored if the request fails.
  • In the mockup the Send button enables as soon as the field has text; Reply does not move focus.
