Layout

  • 375 — glass bottom sheet: handle, title, subtitle, one pill row (label "Name" left, value right), an inline message line under it, full-width UPDATE pinned above the safe area.
  • 768 / 1440 — 440 wide side sheet from the right with the same content; the primary button sits in the sheet footer.
  • States: default (read-only value; tap to edit) · editing · limit (40 characters typed: red message under the field) · empty (hint "Enter Name" + inline message) · loading · error (toast).

Components used

  • Bottom sheet / side sheet · IconButton glass (close)
  • Text field (label-left pill) with helper / error line
  • Button filled L (UPDATE, loading) · Toast (danger)

Motion

  • Open / close — --panel-* (slides up on mobile, slides in from the right from 768)
  • Button and row press — --press-*
  • Error toast — --toast-*
  • Read-only value to input — --reveal-*

Accessibility

  • Dialog named by its title; focus moves into the sheet, is trapped, and returns to the row that opened it.
  • Esc, the close button, scrim tap and (mobile) drag down close it; the primary button is last in tab order.
  • While saving the button is disabled and announces "Saving"; errors are announced in a polite live region.
  • The input is labelled "Name"; the length and empty messages are linked with aria-describedby.

Decisions to confirm

  • The field label is "Name" as rendered in the app (the passed label "Full Name" is not used).
  • The 40-character message appears while the length is exactly 40, as the app; input stops at 40.
  • "Company name cannot be empty" is shown inline on web (never shown in the app — Q-105).
  • Error state mirrors the app: the sheet closes and only the toast shows (Q-106 — keep, or hold the sheet open on failure?).
  • A close button is added in the header (the app closes by drag or tapping outside only).
