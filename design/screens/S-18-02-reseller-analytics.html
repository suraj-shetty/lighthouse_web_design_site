Layout

  • 375 mirrors the Flutter screen: blurred header "Analytics" over one column: intro title + subtitle, 3 stacked metric cards (label, big value, trend on the left; timeframe pill and icon on the right; mini chart underneath), then the "Order Activity Trend" card (title, subtitle, pill, chart with a Y axis, centred legend).
  • 768: the same beside the reseller rail; metric cards stay stacked at full width until there is room for three (960).
  • 1440: 3 metric cards in one row and the activity card full width below, inside the content column. The timeframe picker opens as a popover from the pill.
  • Mini charts: Orders Received is a line, Orders Responded two bars (previous muted, current solid), Orders Accepted a filled line. Each plots two points, previous and current, on a 0 to max × 1.25 scale.
  • Activity chart: 3 series with a point at previous and current; integer Y labels at a "nice" step (here 50, top 150); horizontal grid lines only.
  • States: default (all periods Monthly), tooltip, loading, empty, error (same as empty plus a toast).

Components used

  • Top header · IconButton glass (Refresh, from 768) · Metric card · Filter tag / chip (timeframe pill)
  • Chart (inline SVG, .chart): line, bar, area, multi-line with grid, HTML axis labels, legend, tooltip and a text summary
  • Skeleton · Empty state · Toast (danger) · S-18-03 timeframe sheet / popover

Motion

  • Blocks rise in: --stagger-*; skeleton: --shimmer-*, --skel-*, --reveal-*
  • Applying a period swaps that card's value, trend and chart with --text-swap-* (no network call); pill press: --press-*; sheet: --panel-*
  • Chart points grow on hover / focus with --duration-quick.

Accessibility

  • Heading order: "Analytics" (h1) → "Track Performance & Growth" (h2) → card labels (h3) → "Order Activity Trend" (h2).
  • Every chart has a text summary with the previous and current value of each series (visually hidden figcaption); the SVG itself is hidden from assistive technology.
  • The two chart positions are buttons reachable by keyboard: focus, hover or tap shows the tooltip, and the button name reads all three values.
  • Series differ by more than colour: line style (solid / dashed) and point shape (circle, square, diamond), repeated in the legend and tooltip. Trends say "Up" / "Down" in text.
  • Each pill is a button named with its card and period ("Orders Received period: Monthly"); value changes after Apply are announced by a polite live region.

Decisions to confirm

  • Series colours: there is no chart token (Flutter uses a fixed blue / purple / green). The kit's chart classes are used: Received --accent, Accepted --success-default, Responded --text-default (dashed) in place of purple. Dedicated series tokens are still needed (F-18 open question).
  • Chart component is not in DESIGN_SPEC §8; it is built on the shared .chart classes in lh.css.
  • X-axis labels "Previous" and "Current" are a web addition; Flutter leaves the two ticks unlabelled.
  • Error is not told apart from empty in Flutter. Following Q-06 the web keeps the empty placeholder and adds the error toast; from 768 the Refresh button retries.
  • Every chart has only two points (previous, current), as the API returns today.
  • Zero change is drawn as positive (up icon, success colour), as in Flutter.
  • Glyphs: UserGroup → UserMultiple (not in ICONS.md); Material trending and chevron icons → TradeUp / TradeDown and ArrowDown01 (Q-34).
  • The mockup opens every pill on "Monthly" and cannot apply a new period; the other periods read "+{n} vs previous week / quarter / year".
