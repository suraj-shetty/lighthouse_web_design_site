Layout

  • 375 — glass bottom sheet over the scrim: drag handle, title, subtitle, search field, then either the "SEARCH RESULTS" list, the "SELECTED ADDRESS" card or the empty state, "SAVE".
  • 768 / 1440 — side sheet from the right over Manage Account (440 wide, no drag handle); same order, actions pinned to the bottom.
  • default saved address card (display name + rest of the address) · empty · searching skeleton cards · results · no-results · error (SAVE with nothing selected) · saving · server-error.
  • One address only: picking a result replaces the card. While a query is typed the results take the place of the card.

Components used

  • Bottom sheet / side sheet
  • IconButton glass (close)
  • Search input
  • Place tile (selected card with remove IconButton; result row)
  • Empty state
  • Skeleton
  • Button filled L (SAVE, with loading)
  • Toast danger

Motion

  • Open / close — --panel-*
  • Button press — --press-*
  • Error toast — --toast-*
  • Suggestions — --skel-* / --shimmer-*, then --reveal-*; picked address — --reveal-*

Accessibility

  • Dialog named by its title; focus moves into the sheet, is trapped, and returns to the Manage Account row that opened it; Esc or the scrim closes without saving.
  • While saving the primary button is disabled and announces its busy label; toasts are announced through a polite live region.
  • Search results are a list of buttons; "Searching" and "No results found" are announced as status.
  • The remove button names the address it removes.

Decisions to confirm

  • An address cannot be removed once set: the trash icon clears the draft, but SAVE with nothing selected only shows "Please select an address" (as the app). Confirm whether clearing should be allowed.
  • Search is debounced 300 ms; search and place-detail failures show the "Error" toast with the server message.
  • Results show the suggestion description as one line (the API returns a single string). Addresses are sample data.
  • State server-error shows the sheet as it stays after a failed request, with the "Error" toast (server message, else "Network error occurred" / "Something went wrong. Please try again later."). No retry control, as the app.
