Layout

  • 375 — mirrors the app: full screen without the reseller tab bar. Header "Reject Order?", the order number (no "Order" prefix here), close X. Column: order summary → amber warning → required reason selector → optional note. Blurred bottom bar with "CANCEL" and "REJECT ORDER" (hidden until the order has loaded).
  • 768 — same column beside the glass menu; buttons right-aligned in the sticky bar.
  • 1440 — two columns: warning, reason and note on the left; order summary sticky on the right.
  • "REJECT ORDER" is disabled until a reason is chosen. The reason field opens S-19-07 (a bottom sheet on mobile, a menu anchored to the field from 768).
  • No extra confirmation step. On success the screen closes with no message and the lists refresh.

Components used

  • Top header · IconButton glass (close) · Product card (summary) · Tag · Key / value list
  • Note / banner (warning) · Select (reason trigger) · Textarea
  • Sticky CTA bar · Button translucent L (CANCEL) · Button destructive L with loading (REJECT ORDER) · Button filled M (RETRY)
  • Skeleton · Empty state (load error) · Toast danger

Motion

  • Reason menu — --panel-*; press — --press-*; toast — --toast-*
  • Push / close — --page-slide-* under 768, --panel-* from 768; skeleton — --skel-*

Accessibility

  • "Reject Order?" is the h1. The warning is icon + text, read once on open; never colour alone.
  • The reason control is labelled and marked required; the disabled submit button is described by "Choose a reason to enable this button".
  • Focus starts on the reason field, not on the destructive button. While submitting the button announces "Rejecting order" and the reason field is disabled.

Decisions to confirm

  • Choosing "Other" does not make the note required (as the app).
  • There are no validation messages in the app for this form.
  • The comment sent is "Reason: {reason}" or "Reason: {reason}, additional comments: {note}".
  • The load-error icon uses InformationCircle (app: Alert02, not in ICONS.md).
