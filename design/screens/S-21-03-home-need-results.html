Layout

  • 375: as the app. Back, title and one-line subtitle (centred for build and renovate, left with the SELECT pill for repair and find professionals). Sections in order: professionals, projects (horizontal row, 264 wide), brands (row, 88 wide), products (row, 150 wide). Footer pinned: two half-width outlined buttons, the filled REVIEW REQUEST, then the helper line. No bottom tab bar.
  • 768: grouped professional lists and people cards go to 2 columns; projects, brands and products become wrapping grids; the footer is one row inside the content column with the helper at the left.
  • 1440: 3 columns of professionals, 4 project cards across, content capped at 1120. The footer stays a bottom bar aligned to the content column; the count sits in the button label.
  • States, one per result shape (F-21 section 9): build two groups asked for, all four sections · selected two ticked, "REVIEW REQUEST FOR 2" · saved "SAVED PRIVATELY" disabled · help-me-choose one "PROFESSIONALS" list · browse-only build with no professionals asked for, no REVIEW REQUEST · renovate groups and "RENOVATION PROJECTS" · renovate-browse renovation with no professionals, projects always show · repair "CONTRACTORS" as cards, read-only · repair-select select mode with discs · professional group chips and cards.
  • loading: headings and footer at once, three 120 blocks per group, 240 / 96 / 200 for projects, brands, products. loading-sections: professionals have arrived, the rest still load. empty: only the first group heading with the inline card, other headings stay with no body. error: an inline row with Retry per section.
  • In the mockup the discs work: ticking any row swaps the disabled button and helper for "REVIEW REQUEST FOR n". The professional chips work: All and Architects show the list, every other chip shows nothing, as in the app.

Components used

  • Navigation shell · Top header (glass) with Back · Button translucent M as the SELECT / CANCEL toggle · Chip as filter tabs
  • Shared with Home (f-20.css): section header with action, professional card, project card and row, inline error row
  • New here: grouped professional list (.nr-group, rows with a link and a separate check disc), pickable professional card (.nr-pick), brand chip (.nr-brand), inline empty card (.nr-empty), results footer (.nr-foot-in)
  • From lh.css: Product card (.prod, square image here), Avatar and verified badge, Rating, Skeleton, Sticky footer CTA bar, Toast
  • Check disc from the need flow (.nf-disc), hollow until ticked

Motion

  • Arrival and Back: --page-slide-* (Flutter Transition.cupertino). Sections rise with --stagger-*.
  • Check disc: fill 150 ms then the tick draws after 80 ms over 250 ms in Flutter, mapped to --select-check-fill, --select-check-delay, --select-check-mark.
  • Chips: 150 ms colour in Flutter, mapped to --tabs-*. Cards, rows and buttons press with --press-* (0.98, not the app's 0.97, Q-164).
  • Loading: --shimmer-*, --skel-*, then --reveal-*. Save toast: --toast-*. All of it stops under reduced motion.

Accessibility

  • One h1 (the title) per state; every section is a region named by its uppercase h2, written in capitals in the markup.
  • Each grouped row has two controls: a link "View profile, name" and a checkbox "Send the requirement to name". In select mode the whole card is the checkbox and the avatar stays a profile link.
  • Ticked is shown by the filled disc with a tick, and on cards also by a darker border, not by colour alone. Discs are 44 targets.
  • SELECT / CANCEL carries aria-pressed. Chips are a tablist "Filter by profession". Rating reads "Rating 4.8 out of 5".
  • The helper line is a polite status and describes the disabled button. In the build the count in "REVIEW REQUEST FOR n" must be real text announced politely; the mockup draws it with a CSS counter.
  • "View All" and "Retry" name their section. Loading sections set aria-busy.

Decisions to confirm

  • Glyph swaps (Q-162): Compass01 to Compass, Sofa01 to Sofa03, UserGroup to UserMultiple; Briefcase01 to Briefcase02 and PaintBrush01 to PaintBoard are reserved for the Consultants and Design specialists groups.
  • Colour mapping (Q-161): people cards use the shared card (neutral surface with a hairline) for the app's #F0F1F2; the empty card uses the same; the photo-count badge uses --element-bg-image-count.
  • The photo-count badge sits top right as in need_cards.dart; the shared Home card places it bottom left.
  • Brands show initials: the mockup has no brand logos. A brand opens the Brands screen; in the app it opens the brand's profile.
  • "REFINE RESULTS" stays visible when stage, budget and start are answered, and then does nothing (Q-182). "SAVE PRIVATELY" shows the toast here; the saved state shows the disabled button.
  • Find professionals: chips for groups that were not fetched show an empty list with no message (Q-179). Kept as the app has it.
  • From 768 the footer is a bottom bar, not a side panel, so the sections keep the full width.
