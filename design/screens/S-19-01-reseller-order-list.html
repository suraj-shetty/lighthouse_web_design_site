Layout

  • 375 — mirrors the app: "Orders" title, one scrolling row of 8 status chips, single column of order cards, floating reseller tab bar.
  • 768 — glass menu on the left. New cards flow into a 2-column grid; other statuses stay one column and a card opens Order details (S-19-03).
  • 1440 — master–detail for every status except New: order list on the left, the selected order's details in a sticky pane on the right, with its primary action ("MARK AS COMPLETED" / "RESOLVE ISSUE") in the pane footer. New cards are not tappable in the app, so New is a 3-column grid of cards with "Reject" and "Submit Quote".
  • Chips switch the list in place (try them). The pane shows the first order of the status; in the build, choosing another card swaps the pane.
  • New and Declined cards price = MRP × quantity ("On Request" when there is no MRP); other statuses show this seller's quote total. Missing values show "—".
  • A refresh button replaces pull-to-refresh from 768.

Components used

  • Nav bar / Sidebar (reseller) · Top header · Chip tablist (8 statuses)
  • Order card (list layout): status pill, thumbnail, brand tag or Brand / SKU / Location lines, two metric boxes, total, "View Details"
  • Button translucent S (Reject) · Button filled S (Submit Quote)
  • Detail pane (from 1200): status pill, key / value lists, proof grid, invoice rows, review card
  • Skeleton (4 cards) · Empty state

Motion

  • Chip change — --tabs-*; list swap — --tab-panel-*; the selected chip scrolls to the centre of the strip
  • Card press — --press-*; skeleton to cards — --skel-*, --shimmer-*, --reveal-*
  • Push to details / forms — --page-slide-* under 768; pane content swap from 1200 — --tab-panel-*

Accessibility

  • Landmarks: header, main, reseller nav. "Orders" is the h1.
  • Chips are a tablist; each panel is labelled by its chip.
  • A tappable card is one link named "Order {number}, {product}, {status}". New cards expose two buttons named with the order number.
  • Status is always pill text plus a dot, never colour alone. From 1200 the open order's card carries aria-current.
  • Loading is a busy region; empty and error text are announced.

Decisions to confirm

  • Open (Q-128): status lists load the first 20 orders only, with no paging. Paginate on web?
  • Error has no retry control in the app; from 768 the Refresh button covers it.
  • The empty and error layouts use File02; the app uses LicenseDraft, which is not in ICONS.md.
  • Pane footer leaves out "CANCEL" / "CLOSE": in a docked pane there is nothing to close.
  • Order cards link to S-19-03 with the matching variant through a mockup-only query string.
