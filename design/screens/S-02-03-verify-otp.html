Layout

  • 375 — as the app: circular back button and centred title; four pill code boxes; two-line message with the masked number; VERIFY then the glass resend button pinned to the bottom.
  • 768 — the same content in a centred card; buttons follow the message.
  • 1440 — the same auth card as Sign in with the brand artwork beside it; back sits top-left of the card.
  • States: default (empty, first box focused, countdown running, VERIFY inactive), filled (4 digits, VERIFY active), loading (spinner in VERIFY), error (code cleared, error stroke on every box, toast), resend-ready (countdown finished, "RESEND CODE"). No empty state.

Components used

  • IconButton solid (back)
  • One-time-code input (4 boxes, hint "-")
  • Button filled L (VERIFY: inactive, active, loading)
  • Button glass L (resend: counting, ready)
  • Toast danger

Motion

  • Countdown digits and the label change to "RESEND CODE" — --text-swap-*.
  • Toast — --toast-*; buttons — --press-*; back / forward — --page-slide-* under 768, --panel-* from 768.

Accessibility

  • h1 = title; back is labelled "Back".
  • The four boxes are one group "Verification code, 4 digits" with inputmode=numeric and autocomplete=one-time-code (browser SMS autofill where supported); paste fills all boxes.
  • A failed verify is announced by the toast and the boxes are marked invalid — not by colour alone.
  • The countdown is not announced every second; "You can resend the code now" is announced once.
  • Focus order: back → code → VERIFY → resend.

Decisions to confirm

  • Q-03 applied: "RESEND CODE" is kept as in the app; the build adds the resend method with its API call left commented out.
  • The error toast message is sample server text ("Invalid OTP. Please try again."); the real message comes from the API.
  • While counting, the resend button keeps its glass look and is exposed as disabled.
  • OTP expiry and attempt limits are not shown — the app has none on the client.
