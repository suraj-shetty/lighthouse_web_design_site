Layout

  • 375 mirrors the Flutter screen: cover (25% of the height) under an overlaid row of back, FOLLOW and More; centred avatar overlapping the cover; name, @username, specialization, bio (3 lines, "more"), chips, 3 stats, About row (professionals); pinned icon + label tabs; 3-column square grid; floating Contact bar above the tab bar.
  • Collapsed header (scroll the page): the dark name pill fades in beside back, and FOLLOW / FOLLOWING turns into a round icon button, as in the app.
  • 768: cover becomes a rounded banner under the floating glass bar, identity in a centred column, grid at 4 columns, Contact bar centred at the foot.
  • 1440: summary card (cover, avatar, name, stats, About facts, FOLLOW + Contact) stays pinned on the left; tabs and a 4-column grid use the rest. No floating bar.
  • Role switch = the kind of profile viewed, one per Discover category plus homeowner. Architect, interior designer, contractor and landscape architect share the professional layout with their own details, projects and About page. Stats: Projects / Experience / Team (professionals), Posts / Followers / Following (homeowner, brand), Brands / Orders / Response (reseller). Brand and dealer avatars are square logo tiles; their Shop and Location tabs open S-07-08 and S-07-09.
  • States: default, following (followers +1 on profiles that show the count), follow-pending (spinner), loading, empty, error, private.

Components used

  • Top header (glass on scroll) · IconButton plain / solid · Button filled M (FOLLOW) · Button glass M (FOLLOWING, dark glass in both themes) · Button stroke M (Contact, desktop)
  • Avatar + verified badge · Tag (rating chip, Featured) · Metric cards as a description list
  • Tabs (icon + label) with tab panels · Image grid tiles with video / multiple-media flags
  • Skeleton · Empty state (private) · single-line empty text per tab · Footer CTA bar · Toast (danger) · Spinner

Motion

  • Press on buttons, tiles and the About row: --press-*
  • Header collapse is scroll-linked in Flutter with no recipe in DESIGN_SPEC (Q-93). Here the pill and the follow morph cross-fade with --duration-fast / --ease once the page has scrolled.
  • Tab change: --tabs-*; panel swap: --tab-panel-*
  • Skeleton to content: --shimmer-*, --skel-*, --reveal-*; next page of 21 tiles: --stagger-*
  • Sheets opened from here (S-07-02, S-07-04, S-07-05): --panel-*; toast: --toast-*

Accessibility

  • Landmarks: banner (back, follow, More), main. The profile name is the h1; the header pill repeats it for sighted users only (aria-hidden).
  • Follow exposes aria-pressed, a busy state while pending, and a label that includes the profile name. FOLLOWING and More announce that they open a menu.
  • Tabs are a tablist with tab panels. Tiles are links with alt text; video and multiple-media flags carry text, not an icon only.
  • Stats are a description list (label, value). The private placeholder is a status region; the error toast is a polite live region.
  • All targets are at least 44 px; focus ring is --focus-ring.

Decisions to confirm

  • Error: Flutter shows the preview name and avatar with no message. Following Q-06 the web adds the error toast and each tab shows its empty line; there is still no retry control (F-07 open question).
  • Brand / dealer "Projects" tab shows the tagged grid and the empty line "No tagged posts yet.", as in Flutter (Q-92).
  • Glyphs not in ICONS.md: Folder01 → FolderOpen (Projects tab), Menu01 → GridView (Posts / Inspirations tab), SquareLock02 → Lock, Contact01 → Call02 (Contact button), Store01 → Store02 (About fact).
  • Video and multiple-media flags use PlayCircle and Copy01 (Flutter uses Material icons, Q-34).
  • The Contact bar floats above the mobile tab bar because every signed-in web screen keeps the navigation shell; in Flutter the profile is a pushed screen without it.
  • Desktop keeps FOLLOW and Contact inside the summary card and drops the collapsing header (Q-93).
  • Private and failed profiles keep an empty cover placeholder so the overlaid header row stays legible.
  • Homeowner profiles have no rating or Featured chip in the sample data; chips render only when the profile has them.
