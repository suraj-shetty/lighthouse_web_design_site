Layout

  • 375 — glass bottom sheet (up to 90% height): handle, title and subtitle, content, full-width button pinned above the safe area.
  • 768 / 1440 — side sheet from the right over Manage Account, same content, button in the sheet footer.
  • Field "Add Skill", then the wrap of removable chips, then the result list while typing. The first result row creates a new skill from the typed text.
  • States: default chips only · typing results for "Light" · loading four skeleton rows while searching · creating spinner in the create row · saving button spinner · empty no chips, no list, no empty text (as the app) · error toast, sheet stays open.

Components used

  • Bottom sheet / side sheet · IconButton glass (close)
  • Text field with leading search icon (combobox)
  • Chip, removable
  • Result list rows (menu row) · Skeleton · Spinner
  • Button filled L, with loading · Toast (danger)

Motion

  • Open / close — --panel-* (slides up under 768, slides in from the right from 768).
  • Result list — --stagger-*; new chip — --badge-pop-*; remove — --icon-swap-*.
  • Button press — --press-*; toast — --toast-*.

Accessibility

  • Dialog named by the sheet title; focus moves into the sheet, is trapped, and returns to the row it was opened from; Esc and the scrim close it.
  • Input is a combobox controlling a listbox; the create row is the first option.
  • Chips are a list; each remove button is named "Remove <skill>". Added and removed skills are announced politely.
  • Search starts at 2 characters, 400 ms after the last keystroke.

Decisions to confirm

  • No empty text exists for "no skills yet" — the area is blank, as the app.
  • A search with no matches shows only the create row.
  • Repo fallback error copy is "NO Skills" / "Skill is null" — the toast here shows the generic fallback; confirm final copy.
  • No maximum number of skills in the app.
  • Result names are sample data (the list comes from the API).
