Layout

  • 375 — glass bottom sheet over the scrim: drag handle, title, subtitle, one pill input with a leading icon, focused on open, "UPDATE".
  • 768 / 1440 — side sheet from the right over Manage Account (440 wide, no drag handle); same order, actions pinned to the bottom.
  • One reusable sheet, four configurations — one state each: default Key Contact Role, business-email, key-contact-email, website-url (Website URL for Brand, Business Website URL for Reseller). Manage Account opens the right one with data-open-state.
  • Every validation message has its own state: role-empty, email-empty, email-invalid (same two messages for Key Contact Email), website-empty, website-invalid. saving and server-error are drawn on Business Email.

Components used

  • Bottom sheet / side sheet
  • IconButton glass (close)
  • Text field (pill, leading icon) — focus, error, disabled
  • Button filled L (UPDATE, with loading)
  • Toast danger

Motion

  • Open / close — --panel-*
  • Button press — --press-*
  • Error toast — --toast-*

Accessibility

  • Dialog named by its title; focus moves into the sheet, is trapped, and returns to the Manage Account row that opened it; Esc or the scrim closes without saving.
  • While saving the primary button is disabled and announces its busy label; toasts are announced through a polite live region.
  • The input is labelled by the sheet title and uses the matching type (email, url) for the right keyboard.
  • Validation shows inline, tied to the field with aria-describedby, as well as in the toast the app uses.

Decisions to confirm

  • Inline validation text is a web addition asked for by the spec; the toast (title "Error") is kept so both match the app.
  • Glyph: the app uses UserSettings01 for the role field, which is not in ICONS.md — Manager is used instead.
  • Website accepts anything matching ^(https?:\/\/)?([\w-]+(\.[\w-]+)+)(\/[^\s]*)?$ (case-insensitive); the value is saved as typed.
  • State server-error shows the sheet as it stays after a failed request, with the "Error" toast (server message, else "Network error occurred" / "Something went wrong. Please try again later."). No retry control, as the app.
