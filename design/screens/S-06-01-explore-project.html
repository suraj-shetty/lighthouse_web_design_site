ABOUT

Courtyard House is a weekend home for a family of five, built around an old mango tree on a 12,000 sq ft coastal plot. Every room opens to the central court, so the sea breeze moves through the house without mechanical cooling for most of the year. Deep verandahs shade the west face, lime-plastered walls breathe through the monsoon, and the pool deck in leather-finish Kota stone stays cool underfoot. Rainwater from the tiled roofs is harvested into a 40,000 litre tank below the court.

Layout

  • 375 — one scrolling page with a sticky bottom CTA and no tab bar (as the app). Edge-to-edge media carousel at 45% of the screen height with a round glass back button over it, dots below; then "By {author}" link with the status pill on the right, project title, information card (icon + label left, value right, hairlines), Collaborators / Brands tabs with wrapping chips, ABOUT (3-line clamp), CREDITS card, MATERIALS & PRODUCTS card.
  • 768 — same order in a centred column; the carousel is contained with rounded corners (3:2); the CTA stays sticky at the bottom of the column; navigation rail on the left.
  • 1440 — two columns: carousel on the left (4:5, sticky), on the right author and status, title, SEE FULL PROJECT and the information card as a two-column grid of label-over-value cells. Below, at content width: tabs and About on the left, Credits and Materials on the right.
  • Sections without data are omitted. State empty shows every fallback at once: neutral media block, "By Unknown", "Untitled project", no information card, "No collaborators" / "No tagged users" (the second tab is "Tagged Users" when the project has no brands).
  • Loading (page skeleton) and error (message + Close, plus the toast) exist because the web page can be opened by URL (Q-07), as the app's project loader does.
  • Use the dots (and, from 768, the arrows on hover) to change media; tap a media to open the viewer; tap a tab; tap View More.

  • Image gallery (carousel, dots, previous / next)

Motion

  • Push — --page-slide-* on mobile; shell transition on desktop
  • Carousel — --tabs-* (dots), --tab-panel-* (slide)
  • Tabs — --tabs-*, --tab-panel-*
  • View More — --resize-dur; press — --press-*
  • Media tap — --mediaview-open-dur (S-05-10)

Accessibility

  • Main landmark; the project title is the h1; ABOUT, CREDITS and MATERIALS & PRODUCTS are h2; group labels are h3.
  • The information card is a description list; icons are decorative.
  • Tabs use tablist / tab / tabpanel; the carousel has labelled previous / next and "n of N" on each slide.
  • Back is labelled; the status pill states the status in text; images need alt text (not in the data model).
  • Focus order: back → carousel → author → title → CTA / info → tabs → chips → About → Credits → Materials; the sticky CTA never covers the focused element (page bottom padding).

Decisions to confirm

  • The tab bar is hidden under 768 on this pushed screen so the sticky CTA mirrors the app; the rail / sidebar stays from 768.
  • Status pill uses the success family (the app hard-codes green, Q-33); which status values exist is open (Q-60).
  • Chips use --bg-neutral with --element-stroke-filter-tags-default: the fill token --element-bg-filter-tags-default is white in the dark theme and unreadable with light text.
  • Glyphs not in ICONS.md: TaskDaily01 → Contracts (Project Scope), Resize01 → Ruler (the four area rows), broken-image → Image02, chevrons → ArrowDown01 / ArrowUp01.
  • Brand, credit and material chips are not links (Q-62). Collaborators and the second tab can show the same people (Q-59).
  • In the mockup the carousel is driven by its dots and arrows (no swipe); error copy is the server message (sample text).
