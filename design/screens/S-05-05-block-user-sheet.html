Layout

  • 375 — glass bottom sheet sized to its content: drag handle, title, explanatory body, Cancel and Block side by side at equal width.
  • 768 / 1440 — centred destructive-confirm dialog (400 wide) with the same content.
  • Title uses the author's full name, else the user name; with neither it reads "Block this user?" (state no name).
  • Blocking closes the sheet, reloads the feed and shows "Blocked / You will no longer see their content." If the server reports the user is now unblocked the toast reads "Unblocked / You can see their content again."

Components used

  • Bottom sheet (under 768) / Modal dialog, destructive confirm (from 768)
  • Button stroke L (Cancel) · Button destructive L (Block, with loading)
  • Toast — success, danger

Motion

  • Open / close — --panel-* (sheet) · --modal-* (dialog)
  • Button press — --press-*; toast — --toast-*

Accessibility

  • alertdialog named by its title and described by its body; initial focus on Cancel; focus trapped.
  • Esc, scrim tap and drag down cancel; focus returns to the card's "…" button, or to the top of the feed after the reload.
  • While sending both buttons are inert and Block announces "Blocking".
  • The destructive action is identified by its label as well as colour.

Decisions to confirm

  • Spec lists Cancel as a translucent button with a --stroke-soft outline; the design uses the stroke button from the shared catalogue.
  • The endpoint is a toggle (Q-55): confirm whether "Unblocked" can really be reached from this sheet.
