No bottom tab bar.
  • 768: title and search share one row, chips beneath; cards in 2 columns.
  • 1440: the same bar; 3 or 4 columns of cards as the menu collapses or expands, content capped at 1280.
  • States: default "All projects", 8 projects · type arriving with a type, "Residential" selected · searching "villa" typed, 2 matches · no-match projects loaded but the chip matches none: lead, "Healthcare · 0 projects", empty text · empty the server returned nothing: empty text only · error inline row with Retry, filters kept · loading two blocks (four from 768), header, search and chips stay usable.

Components used

  • Navigation shell · Top header (glass) with Back · Input (outlined, as the app, not the elevated search input) · Chip as single-select tabs
  • Project card (shared, f-20.css) with the author line and a 4:3 cover · Image count badge · Inline error row (shared) · Skeleton · text-only empty lines

Motion

  • Arrival and Back: --page-slide-*. Cards rise with --stagger-*; a filter change uses --reveal-*.
  • Chip change: --tabs-*. Card press: --press-*. Loading: --shimmer-*, --skel-*.

Accessibility

  • h1 "Explore projects". The search field is a search landmark labelled "Search projects".
  • Chips are a tablist "Project type". The result line is a polite status that announces the count after each filter change; counts use tabular figures.
  • Each card is one link named "title, by author, place, n photos"; the cover has empty alt text.
  • The filter glyph does nothing in the app, so it is hidden from assistive technology and cannot take focus. The loading list sets aria-busy.
